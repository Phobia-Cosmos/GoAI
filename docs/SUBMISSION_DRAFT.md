# GoAI 初赛内容定稿

更新日期：2026-08-13

本文件提供作品简介、PPT/PDF 逐页文案、Demo 录屏讲解顺序、答辩问答和合规声明。录屏由项目成员自行完成；演示统一使用模拟企业和新生成赛局，不展示真实队伍映射、完整规则参数、策略阈值、固定种子或逐步内部轨迹。

## 作品简介（500 字以内）

GoAI 是面向企业经营沙盘的部分可观测协同决策系统。比赛中，参赛者需要在订单竞争、产品与市场资格、产能建设、原料采购、融资、交付和破产风险之间持续权衡，但真实决策只能获得本企业状态、公开订单和规则允许的信息。GoAI 将规则、盘面与历史操作转换为结构化状态，由资金、资格、产能、供应履约、订单组合和风险六个专业 Agent 共同生成可执行方案；用户可以逐项修改并确认，确定性裁判内核再独立完成订单分配、财务结算、违约、破产和排名。系统支持单人对 Agent、多人对 Agent、纯用户和纯 Agent 完整比赛，并记录可审计、可反事实重放的动作与反馈。当前 XA 三种子校准中，存续企业平均得分达到真实比赛的 97.93%，获单后交付率为 93.26%。创新点在于将“部分可观测协同决策、确定性规则验证、人机确认和闭环评测”统一到一个可运行平台；LLM 可用于题面理解和方案解释，但不直接修改财务真值。

## PPT/PDF 逐页内容

### 第 1 页：GoAI 企业经营协同决策系统

主标题：在部分可观测比赛中，让每一次经营决策可执行、可解释、可验证。

页面信息：项目名称、团队名称、赛道名称；背景使用脱敏后的比赛操作界面，不出现真实队伍名、学校名或订单归属。

讲述重点：GoAI 不是聊天机器人，也不是只预测一个分数的模型，而是能进入季度决策闭环、提出动作并接受环境反馈的辅助决策系统。

### 第 2 页：为什么这类比赛难以靠单点最优解决

页面文案：

- 决策跨越 5 年 20 个季度，一个季度的融资、资格和扩产会改变后续可接订单。
- 订单、产品、市场、ISO、产线、BOM、现金和回款相互约束。
- 对手私有状态不可见，获单结果只有统一分配后才能确认。
- “预计不破产”不等于不会破产，最终结果必须由独立环境结算。

讲述重点：难点不是某一张表算不出来，而是短期现金、长期能力和不确定对手必须在同一决策中统筹。

### 第 3 页：系统要服务的真实用户闭环

页面流程：读取规则与当前盘面 → 形成我方可见观察 → 生成联合建议 → 人工增删修改 → 提交赛场 → 接收实际获单与财务反馈 → 下一阶段重新规划。

页面文案：系统只控制我方一家企业；其他企业在真实比赛中仍由其他选手决策，在本地训练中才由多种对手策略模拟。接入时可以从比赛任意季度开始，只需要提供此前已知的本企业操作和当前可见盘面。

### 第 4 页：从杂乱比赛文件到统一数据契约

页面文案：

- 输入层：题面规则、企业初始状态、公开订单、本企业操作、季度反馈和年度报表。
- 标准层：规则包、观察、动作、事件、状态、报表和终局结果七类结构化对象。
- 来源层：区分 observed、derived、inferred 和 simulated，避免把历史推断写成正式规则。
- 可见性层：终局订单归属仅用于离线校准，在线决策不读取未来信息或对手私有状态。

讲述重点：统一数据契约使真实比赛接入、模拟训练、历史分析和 Agent 评测使用同一套接口。

### 第 5 页：确定性裁判内核

页面文案：规则引擎负责动作合法性；比赛环境负责同步阶段、订单冲突和全局推进；财务状态机负责贷款、采购、BOM、生产、交付、回款、税费、折旧、报表、违约、破产与排名。

讲述重点：Agent 只能建议动作，不能直接写现金、权益或得分。即使 Agent 认为方案安全，环境仍会根据真实提交后的状态判定是否违约或破产。这保证评测结果不会被生成模型的文字结论覆盖。

### 第 6 页：我方企业内部的六专业 Agent

页面文案：

- 资金 Agent：融资期限、现金安全和应收管理。
- 资格 Agent：产品、市场和 ISO 的开发节奏。
- 产能 Agent：厂房、产线、安装、转产和可执行批次。
- 供应履约 Agent：BOM、原料、在制品、生产、交付和违约成本。
- 订单组合 Agent：在利润、交期、资格和容量约束下选择订单组合。
- 风险 Agent：提交前重放联合动作包，检查破产、违约和硬约束。

讲述重点：六个模块不是各自提交一份互相冲突的答案，而是共享同一决策黑板，最终输出一份按依赖顺序排列的动作包。

### 第 7 页：双阶段决策解决“先申领、后获单”的不确定性

页面流程：经营与申领阶段 → 所有企业同步提交 → 环境统一分配订单 → 仅反馈本企业实际获单 → 获单后履约阶段 → 统一结算。

页面文案：第一阶段不能把最终导出表中的企业归属当作预先已知信息；第二阶段必须依据实际获单重新安排融资、采购、生产和交付。共享订单冲突和竞单方式采用可替换规则模块，便于以后适配不同赛制。

### 第 8 页：可点击的完整比赛平台

页面文案：

- 支持单人对 Agent、多人对 Agent、纯用户和纯 Agent。
- 覆盖贷款、开发、厂房、产线、采购、生产、交付、广告、选单、竞单和信息购买等操作。
- 人工既可从空动作包逐项操作，也可获取联合建议后修改再提交。
- 纯 Agent 赛局可逐阶段推进或直接运行到终局；终局可查看排名并导出审计记录。

讲述重点：浏览器只是操作和展示层，任何按钮都要通过服务器规则与状态机校验；获单后不允许的动作会即时禁用并由服务端再次拒绝。

### 第 9 页：可核验的效果，而不是单一高分

页面表格：

| 指标 | GoAI 三种子均值 | 真实 XA | 相对水平 |
| --- | ---: | ---: | ---: |
| 存续企业平均得分 | 1536.90 | 1569.39 | 97.93% |
| 存续企业平均权益 | 619.36 万元 | 584.22 万元 | 106.01% |
| 发展潜力 | 142.66 | 149.67 | 95.32% |
| 每场获单 | 497.67 | 561 | 88.71% |
| 每场交付 | 464.33 | 544 | 85.36% |
| 获单后交付率 | 93.26% | 96.97% | 相差 3.70 个百分点 |

页脚说明：27 家企业、20 个季度、每场 796 条订单；三种子全部会计平衡，动作拒绝为 0。真实 XA 用于数量级校准，不代表逐事件精确复刻。

讲述重点：得分、权益、发展潜力和履约质量已经接近真实比赛；仍少约 63 个获单和 80 个交付，模拟平均少破产约 2.33 家，因此不宣称全面超过真实选手。

### 第 10 页：为什么获单从偏低提升到当前水平

页面文案：旧策略只按当前产能判断订单，遗漏产线安装完成时间、忙线释放、库存、在制品、交期窗口、复杂 BOM 和终局边界，导致大量可执行订单被误判为不可接。新版按每条产线的时间表估算可执行容量，并在获单后重新规划供应和履约；风险模块同时检查现金与年末结算，使获单提升不会依赖跳过财务约束。

讲述重点：提升来自决策模型和时序修复，不是修改初始现金、放宽破产条件或抬高评分公式。剩余差距需要订单、产线、BOM、融资和回款的多季度联合搜索，而不是继续调一个阈值。

### 第 11 页：创新、工作量与专业性

页面文案：

- 从原始 XLS/XLSX、题面和报表建立统一可追溯数据层。
- 实现 5 年 20 季度的因果模拟、双阶段订单分配和完整财务状态机。
- 建立只服务我方企业的六专业协同 Agent 与部分可观测接口。
- 同时提供历史回放、反事实分支、异质对手、随机订单和 Web 比赛平台。
- 用 106 项自动测试、浏览器端到端流程、会计平衡和多种子指标共同验收。

讲述重点：新颖性不在于堆叠多个模型名称，而在于把“建议、执行、反馈、再规划”做成可运行并能被独立裁判验证的闭环。

### 第 12 页：安全边界与下一阶段

页面文案：当前演示只使用公开规则、脱敏/模拟数据和聚合指标；LLM 只用于题面理解、工具编排与解释，不负责财务真值。下一阶段将完成 4–8 季度联合滚动搜索、更多订单种子与对手组合压力测试、真实赛场状态适配和授权后的数据闭环。

开放计划：逐步开放数据契约、示例模拟数据和策略接口；完整规则参数、真实企业明细、内部阈值和可复现校准轨迹不随初赛材料发布。

结束语：让复杂经营决策从“凭经验提交”变成“可计算、可确认、可反馈、可复盘”。

## 评委常见问题与回答

**1. 这是不是用大模型直接生成经营决策？**

不是。当前可运行版本不依赖 LLM。规则、财务、订单分配、合法性和基础策略由确定性代码执行；LLM 后续只承担题面理解、候选规划、工具调用和解释，不能直接修改现金、权益或得分。

**2. 为什么需要多个 Agent，而不是一个统一模型？**

经营动作存在明确但相互依赖的专业约束。分模块可以分别审计资金、资格、产能、供应、订单和风险，再通过共享状态与风险重放形成一个联合动作包。这样既保留全局统筹，也能定位错误来自哪个约束。

**3. 多 Agent 是不是控制所有参赛企业？**

不是。六个专业 Agent 都服务我方同一家企业。真实比赛中的其他企业由其他选手控制；本地才用不同对手策略构造不确定性，以训练我方系统的鲁棒性。

**4. 如何保证没有读取未来订单归属或对手私有信息？**

在线观察经过字段白名单过滤，第一阶段只包含公开订单和我方私有状态。订单归属由所有企业提交后统一产生，之后只反馈我方获单；历史终局字段只用于离线校准，不能进入在线策略输入。

**5. Agent 说方案不会破产，就一定不会破产吗？**

不一定。Agent 的风险预演只是提交前评估；最终合法性、现金、权益、违约和破产都由独立环境根据实际状态转移判定。环境已能产生破产企业，Agent 无权覆盖裁判结果。

**6. 你们是否完全还原了真实 XA 裁判？**

没有这样宣称。公开资料没有包含原服务端的全部结算顺序和参数。已观察内容按证据实现，缺失内容采用传统沙盘规则和显式推断，所有字段保留来源标签。当前系统是经过 XA 数量级校准的因果模拟器。

**7. 为什么当前获单和交付仍低于真实比赛？**

主要差距在绝对订单吞吐和种子波动。当前每场平均比真实少约 63 个获单、80 个交付；后续需要让订单、专线、复杂 BOM、现金、贷款和回款进行 4–8 季度联合搜索，而不是放松财务约束来追单项数字。

**8. 目前的实验是否足以证明系统在任何赛场都有效？**

不足。三种子结果证明系统已经达到接近真实 XA 的基础数量级，并通过会计平衡和动作合法性检查，但对规则变化、极端订单和未知对手的鲁棒性还需要扩大种子、对手组合和最差场景评测。

**9. VPD 在系统中是什么角色？**

VPD 是比较人工和 Agent 决策方向的一个验收指标，不是唯一目标，也不直接驱动财务状态。正式得分、权益、发展潜力、获单、交付、违约和破产概率需要联合评价，防止策略只优化单一分数。

**10. 如何接入真实比赛？**

适配器把规则、当前公开盘面、本企业历史操作和当前私有状态转换为统一观察。Agent 输出候选动作，由用户最终确认并提交；系统再接收订单分配和结算反馈进入下一轮。对手未知不影响接口，只会增加决策的不确定性。

**11. 与传统沙盘平台的区别是什么？**

传统平台主要负责录入和裁判；GoAI 在裁判内核之外增加了部分可观测决策接口、单企业专业 Agent、人机协同、异质对手模拟、反事实分支和策略评测，使平台既能承载比赛，也能训练和验证决策系统。

**12. 当前工作量如何核验？**

可以通过统一数据契约、20 季度环境、完整财务状态机、双阶段订单机制、六专业 Agent、四种比赛模式、终局导出和 106 项自动测试交叉核验；Demo 还会实际运行创建、推荐、修改、提交、反馈和终局流程，而不是只展示静态页面。
