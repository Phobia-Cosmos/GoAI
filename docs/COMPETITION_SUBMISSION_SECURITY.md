# 初赛提交与保密边界

更新日期：2026-08-13

## 结论

当前项目没有发现已提交的邮箱、手机号、API 密钥、私钥或密码；但不能据此宣称“没有隐私问题”。公开仓库已经是 `Phobia-Cosmos/GoAI`，且包含处理后的真实比赛企业名称、学校字段、规则实现、完整实验轨迹和可运行模拟器。公司昵称与学校虽然通常不是个人敏感信息，但仍属于参赛数据和组织信息，是否可以公开取决于数据授权和赛事要求。

项目还存在更现实的保密风险：公开源码、规则参数、Agent 阈值、订单生成方式、完整实验轨迹和部署入口会显著降低他人复现系统的难度。这属于技术与竞赛策略保密，不等同于个人隐私。初赛只要求作品简介、方案 PPT/PDF，以及可选 Demo 或视频，并不要求公开完整源码；因此初赛阶段不应把完整仓库、真实企业明细或完整实验轨迹作为附件提交。

## `artifact/` 的处理

`artifact/` 目前只作为本地材料来源，不进入 Git：

- `boundless.pdf`：赛事手册，包含初赛提交格式、评审维度、数据合规和后续阶段要求。
- `企业经营沙盘 AI 分析引擎.pptx`：旧方案材料和设计历史，含 19 页演讲者备注、作者元数据 `Kimi` 和 AIGC 自定义元数据，不应原样提交。
- `报表制作注意事项.pdf`：报表口径参考。
- 两张 PNG：提交要求或页面截图参考。

旧 PPT 中的实验数字、模型数量和准确率不能直接作为当前项目结果引用。它描述的是另一套早期 VPD-OE 设计；当前可核验数字应以 `data/experiments/xa_collaborative_calibration_v17/summary.json` 和 `docs/CURRENT_VERSION_SUMMARY.md` 为准。

## 初赛可以展示的内容

建议提交一个“可解释但不可一键复现”的材料包：

1. 500 字以内作品简介：说明企业经营比赛中的目标用户、公开信息受限、跨季度决策复杂、人工容易漏算和系统提供人机协同闭环。
2. PPT/PDF：展示问题背景、双阶段比赛流程、确定性规则内核、六专业 Agent 协同、部分可观测边界、点击式 Demo、审计日志和 v17 的聚合指标。
3. Demo 视频或现场演示：使用脱敏的 `SIM_*` 数据或重新生成的模拟订单；展示创建比赛、Agent 推荐、人工修改、订单分配、获单后履约和反馈回流。
4. 结果页：只展示聚合区间和相对真实 XA 的比例，不展示企业到队伍的映射、完整订单归属、逐季动作、阈值和可直接复跑的随机种子组合。
5. 合规页：声明当前演示使用公开规则、模拟数据和经过结构化处理的比赛样例；不上传个人联系方式，不使用未授权商业秘密；真实比赛数据仅用于内部校准或在取得授权后使用。

## 初赛不应提交的内容

- `data/processed/v2/matches/*/teams.jsonl` 中的真实公司昵称、学校字段和逐企业结果。
- `data/experiments/xa_collaborative_calibration_v17/` 的完整 `actions.jsonl`、`observations.jsonl`、`states.jsonl`、`trace.jsonl` 和订单分配日志。
- 完整 `rules.json`、订单生成参数、Agent 资金阈值、产能筛选逻辑、对手策略和消融脚本。
- 真实 XA 的逐季企业轨迹、终局订单归属、未公开的中途反推字段和原始 XLS/XLSX。
- `artifact/` 中带演讲者备注、作者元数据或旧实验结论的 PPT 原文件。
- 任何 `.env`、令牌、服务端地址、私人数据路径或本地会话文件。

## 建议的提交结构

```text
submission/
  README.pdf                 # 作品简介，500 字以内
  proposal.pdf               # 方案 PPT 导出的 PDF
  demo.mp4                   # 可选，使用脱敏模拟数据
  demo_screenshots/          # 可选，界面和反馈截图
  sample_data/               # 仅放小规模模拟输入输出
  compliance.md              # 数据来源、授权、脱敏、边界和依赖说明
```

初赛材料中的源码链接可以指向一个单独的展示仓库或临时只读分支，不要直接指向包含完整历史数据和实验轨迹的开发仓库。若赛事后续明确要求代码，应先建立发布分支，移除真实企业明细、内部参数、旧材料元数据和可重放完整轨迹，再发布可运行的最小 Demo。

## 发布前检查清单

- 用 `git ls-files` 检查待发布文件，不仅检查工作区目录。
- 搜索邮箱、手机号、密钥、私钥、密码、`.env` 和本地绝对路径。
- 检查 PDF/PPT 的作者、修订者、演讲者备注、批注、隐藏页、嵌入对象和外部链接。
- 将真实企业标识替换为 `TEAM_01` 等不可回溯标识；聚合统计至少按一场比赛或多场均值展示。
- 保留结果来源标签：`observed`、`derived`、`inferred`、`simulated`，不要把推断值写成真实裁判规则。
- 用一个全新的模拟种子执行 Demo，确认提交材料中的输入输出不能直接恢复真实 XA 的终局归属。
- 重新核对第三方依赖、模型名称、许可证、数据授权和部署边界。

## 推荐对外表述

“系统基于公开规则、脱敏/模拟数据和确定性沙盘环境，为单个参赛企业提供部分可观测条件下的多模块协同决策建议。Agent 只输出可审计候选动作，环境独立完成订单冲突、财务结算、违约和破产判定。当前 Demo 重点展示任务闭环和可验证性；完整规则参数、真实轨迹和内部校准数据不在初赛材料中公开。”

这段表述既符合赛事要求的任务闭环、技术架构、数据合规和开放计划，也不会承诺“完全复刻真实裁判”或暴露足以直接复现系统的细节。
