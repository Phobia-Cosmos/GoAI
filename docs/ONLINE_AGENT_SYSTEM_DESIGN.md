# GoAI 在线滚动决策系统设计

GoAI 只部署给我们拥有的一家参赛企业，不为其他真实参赛者提供 Agent。目标不是从比赛第一季度开始自动生成一条固定方案，而是在比赛任意允许的时刻接入：系统读取 XA 规则、本企业截至接入时刻的完整操作历史和当前状态、当时已经公开的信息，生成可执行决策；比赛平台返回执行结果后，系统更新状态和对未知环境的判断，再生成下一轮决策。最终优化目标是提高我方终局比赛得分与排名，同时控制破产、违约和现金断裂风险。本地模拟中的其他企业 Agent 只是不可控对手模型和压力测试样本，不属于真实部署系统。

## 信息边界与运行闭环

在线系统必须把三类信息严格分开：

| 信息区 | 典型内容 | 用途 |
| --- | --- | --- |
| Agent 可见输入 | XA 规则、本企业全部既往操作、当前本企业完整状态、已发布订单和公共公告 | 当前决策 |
| Agent 内部估计 | 对手产能、订单竞争强度、未来需求和规则不确定性的概率分布 | 风险情景与候选仿真，不得冒充事实 |
| 裁判/离线真值 | 其他企业私有状态、全局未公开订单、未来事件、最终排名 | 训练评估和模拟环境推进，不得进入在线观测 |

```text
比赛数据适配器
    ↓
接入快照：规则 + 本企业历史 + 当前本企业状态 + 已发布公共信息
    ↓
状态重建与可信度检查
    ↓
候选动作生成 → XA 硬约束过滤 → 多情景/多步模拟
    ↓                                      ↑
指标组合与风险排序                         对手与订单不确定性模型
    ↓
Agent 建议或人工确认 → 提交比赛系统
    ↓
执行反馈 → 事件日志 → 更新状态和策略 → 下一次决策
```

接入不要求从 `Y1Q1` 开始。设接入点为 `t`，系统的第一份输入应是 `snapshot(t)`，后续每次提交动作 `action(t)` 后接收 `feedback(t→t+1)`，生成下一份 `snapshot(t+1)`。接入前本企业的操作历史用于重建未完成承诺，例如贷款到期、研发剩余期数、原料到货、在制品完工、应收款到账和订单交付期限；不能仅提交当前现金余额。

当前 `FullCompetitionArena` 已经具备全局环境中的观测、联合动作、订单冲突处理、财务结算、反馈和下一观测循环，也隔离了不同 Agent 的私有状态。`OwnedEnterpriseRobustPolicy` 只控制我方企业，并已实现滚动多订单组合、不确定对手情景、可选付费情报、拒绝反馈和下一周期调整。`data/simulations/xa_fixed_v1/` 已完成一场固定 XA 参数的 27 企业、20 季度比赛，并保存完整 Agent I/O、全局裁判轨迹、报表、排名和比赛式 XLSX。尚需补充的是面向真实比赛平台的适配器、任意时点完整快照导入、公共信息发布时间标注以及人工确认/提交接口。

## 真实与模拟数据如何使用

`data/agent_ready/v1/xa/` 是统一入口。真实数据和模拟数据采用相同的决策转换语义，但用途不同：

- 真实 XA 用于分析完整经营轨迹、寻找高分企业的决策组合、建立行为先验和检验历史事实。最终排名只能作为整条轨迹的结果标签，不能证明其中每个动作在局部都是最优。
- 模拟 XA 用于反事实测试、不同对手组合和订单种子压力测试、策略消融以及多 Agent 竞争。模拟动作来自启发式策略，只是基线，不应直接当作专家示范。
- 在线 Agent 的观测只能读取 `observation`；`offline_labels` 由训练器和评估器读取。任何把终局排名、未来反馈或其他企业私有数据并入当前观测的训练方式都会造成信息泄漏，离线成绩会虚高而无法在线复现。

优秀决策分析应以“轨迹片段 + 当时状态 + 后续结果”进行，而不是只统计动作频率。建议比较冠军、稳定高分、低分和破产企业在相似资源状态下的动作差异，识别现金缓冲、融资期限、产能扩张节奏、产品/市场开发顺序、订单承诺强度和交付稳定性等组合模式，再放入模拟环境做反事实验证。

## VPD 的定位

VPD 不是系统必须依赖的核心，也不能单独决定每一步动作。它更适合作为可插拔的战略诊断指标：描述企业当前发展阶段或长期潜力，为“保守、均衡、扩张”等策略档位提供一个方向性信号，并在多个可行动作终局收益接近时参与排序。

系统真正不可缺少的是：XA 硬约束、现金安全、偿债能力、订单履约约束和与正式终局得分一致的评价。默认可以先使用现有的现金安全、偿债、盈利、履约、产能利用和终局得分代理指标。VPD、PSS、EPSS 等均通过 `DecisionMetric` 插件接入，只读取候选仿真结果，不修改环境状态，也不绕过硬约束。

是否保留 VPD 应通过消融实验决定：在相同连接时点、订单种子和对手组合下，对比启用与关闭 VPD 后的平均终局得分、排名分位、破产率、违约率、最小现金和决策稳定性。如果 VPD 不能在留出比赛或多种模拟场景中稳定提高结果，就保持关闭；如果它只提高发展潜力但降低现金安全或正式得分，也不能作为默认指标。

## 近期实现顺序

1. 定义并校验 `snapshot(t)` 的完整字段，新增真实比赛接入适配器，支持从任意季度恢复本企业状态和未完成承诺。
2. 给公共信息增加明确的 `available_at`，特别是订单池、广告结果、排名公告和年度公开报表；无法确认发布时间的字段默认不进入在线观测。
3. 让模拟导出直接保存每个 Agent 每步的完整 `AgentObservation`、动作、反馈和下一状态，形成可直接训练的同构数据。
4. 建立历史轨迹分析和反事实实验：从 XA 高分、低分与破产企业提取关键分叉点，在多个隐藏对手状态与订单种子下重放候选动作。
5. 先验证不含 VPD 的基础策略，再分别接入 VPD、PSS、EPSS 做指标消融，最终仅保留能在留出场景中改善正式目标的指标。
