# 模块化决策系统基础设计

基础版本将规则执行、状态维护、候选生成、指标评价、策略选择和多企业编排分开。VPD 只是可插拔指标之一，不是系统入口，也不参与现金、库存、贷款或财务报表的确定性计算。

## 规则从结果中的可识别等级

| 等级 | 判定标准 | 示例 | 使用方式 |
| --- | --- | --- | --- |
| observed | 正式规则原文或平台直接导出 | XA 初始现金 675W | 正式规则 |
| identified | 多个事件下只有一个参数能解释所有转移 | 每季管理费 14W | 可执行规则，保留证据 |
| inferred | 存在合理解释，但不是唯一解释 | 某次在建投资对应哪条产线 | 仿真规则，需置信度 |
| inherited | 本场缺失且无冲突，复用 XA 接口语义 | 状态字段和审计协议 | 兼容层 |
| simulated | 为压力测试或训练接口生成 | 旧场次未分配订单 | 不作为历史事实 |

仅靠最终三张报表通常无法唯一确认税费时点、选单优先级和季度结算顺序。确认这些规则需要动作前状态、动作参数、动作后状态，或正式题面。

## 模块边界

1. `RulePack`：比赛参数、合法动作、结算顺序和评分规则。
2. `Dynamics`：唯一可以修改企业和公共状态的确定性状态转移层。
3. `CandidateGenerator`：生成保守、平衡、增长或搜索得到的动作方案。
4. `MetricSuite`：对仿真结果计算现金安全、偿债、盈利、履约、产能利用和最终得分代理指标。
5. `DecisionStrategy`：通过可替换权重或排序规则选择候选。
6. `AgentPolicy`：接收可见观察并输出动作；可由规则、优化器、统计模型、强化学习或 LLM 实现。
7. `MultiAgentEnvironment`：组织多个企业同步推进、共享订单竞争和公共信息更新。
8. `Evaluator`：历史回放、指标消融、跨比赛留出测试和多 Agent 联赛。

## 当前实现

`src/goai_data/decision_system.py` 已提供：

- 六个不依赖 VPD 的基础指标。
- `safety`、`balanced`、`growth` 三套策略配置。
- 指标权重对比和逐指标移除实验。
- 统一 `AgentPolicy` 与 `MultiAgentEnvironment` 协议。
- `HistoricalReplayArena`，可让同一比赛全部企业按 20 季轨迹同步回放。
- `ArenaRunner`，未来可以在不修改 Agent 和指标层的情况下替换为 XA 确定性动力学。

`src/goai_data/xa_dynamics.py` 已提供 `XADynamics` 和 `XACounterfactualArena` 基础版本。它支持 XA 的现金与承诺状态转移、管理费、短贷、原料、开发、厂房、产线、生产、交付和季度结算，并明确拒绝尚未接入 resolver 的共享订单动作。它目前仍标记为 `cash_and_commitments_partial_accounting`，尚未完成完整折旧、税费、市场广告排名、选单/竞单冲突、破产排名和正式三张报表。

下一步应实现 `OrderAllocationResolver` 和完整 `XAAccountingDynamics`，负责共享订单、广告排名、选单/竞单冲突、折旧、税费、企业动作、破产和最终排名。之后才能把反事实决策 Agent 接入 Arena。

## 指标替换与比较

VPD 可以作为新指标实现 `DecisionMetric.evaluate()` 并注册到 `MetricSuite`。不使用 VPD 时，可以比较现金安全、偿债能力、权益增长、订单履约、产能利用、最终得分代理，以及后续加入的最大回撤、违约风险、机会成本和策略稳定性。

每次实验必须记录规则包、订单种子、Agent 版本、指标集合、权重、对手组合和结果。最终判断不能只看平均得分，还要同时检查非法动作率、破产率、最差分位数、跨种子方差、报表一致性和对未见比赛的泛化能力。
