# 单企业鲁棒决策 Agent 系统

GoAI 的部署对象只有我们拥有的一家参赛企业。真实比赛中的其他企业不运行 GoAI，也不向 GoAI 暴露私有状态；本地模拟中的其他企业策略只是对手样本，用于测试我方策略面对不同订单竞争、扩张强度和风险偏好时的稳健性。全局模拟环境拥有裁判真值并负责订单分配、财务结算、违约、破产和排名，我方 Agent 的预测不能覆盖环境裁决。

## 在线边界与闭环

`OwnedEnterpriseRobustPolicy` 每次只接受与 `agent_id` 一致的 `AgentObservation`。输入包括我方当前完整状态、我方历史承诺、当期已发布订单、脱敏后的公开中标结果，以及规则明确允许并由我方付费获得的情报。对手现金、库存、贷款、在制品、未提交动作、未来订单和裁判内部竞价 trace 均不进入规划器。

```text
我方企业快照 + 已发布公共信息
        ↓
复杂经营组合：融资、产品/市场/ISO、厂房、多条产线、采购、多产品生产、广告、抢单、交付
        ↓
多订单组合枚举
        ↓
安静 / 一般 / 拥挤 / 全部意外中标等隐藏对手情景
        ↓
现金、产能、交期、违约、破产和终局得分联合评估
        ↓
统一动作包 → 比赛环境执行和裁决
        ↓
接受 / 部分拒绝 / 财务事件 / 新状态反馈
        ↓
下一季度重新规划
```

系统不是一次性生成五年固定方案，而是滚动规划。默认前瞻 8 个季度，每个决策点最多检查 12 个优先订单、并行申领 3 个订单、并行开发 3 项资格、新建 3 条产线、安排 8 个生产动作、10 个交付动作和 3 组市场—产品广告，并在 48 个不确定情景中评估。场景零固定为压力情景：假设所有申领都中标且投入成本偏高，避免把“可能抢不到订单”错误地当作现金安全来源。

经营候选不再采用“有未交订单就停止扩张”“第四年以后禁止研发和广告”的硬编码。当前候选包括稳定现金、履约补给、资格建设、产能建设、市场获取、平衡组合和增长组合。每个候选动作都先由 `FullFinancialDynamics` 逐项执行，非法动作、现金破产、短贷到期、在建产线付款、原料到货付款、研发分期、年度维护和租金都会进入风险判断。已有订单不会机械阻止新订单；只要共享产线联合排程、现金情景和交付窗口仍可行，Agent 可以滚动增加承诺。

第一年尚无公开订单时，系统使用规则宇宙形成最小经营闭环，而不读取未来订单：开发基础产品和市场、购买最小厂房及一条基础产线、准备少量原料。之后根据已发布订单和公开竞争结果再扩大产品、市场、ISO、产线、采购和广告。柔性线在多产品排程中只能计一次共享容量，不能分别重复记入每个产品。

环境对非法动作采用单企业拒绝语义：该动作生成 `action_rejected`，比赛和其他企业继续推进。反馈同时写入我方下一观测的 `last_action_feedback`，并调用 Agent 的 `observe_feedback()`，形成提交—执行—反馈—调整闭环。环境仍在每个结算阶段独立判定破产和违约，因此“预测风险低”不等于实际结果保证安全。

## 对手与付费信息

`PartialOpponentModel` 只根据公开中标记录更新竞争强度和公开胜率，不读取对手私有状态。对手策略在本地试验中分为保守、混合和激进三组，它们是压力测试变量，不是对真实参赛者行为的确定预测。

信息购买通过可选规则 `financial_rules.information_purchase` 启用。环境扣除费用后，仅把规则允许的字段写入购买方的私有 `intelligence_reports`。XA 历史中观察到每次 5 万元的 `Spy` 记录，但这些记录位于 Y6Q1、超出当前五年经营窗口，因此固定 XA 场景默认关闭该能力；只有比赛正式规则明确允许时才能开启。

## 当前复杂决策实验

当前版本 `owned_enterprise_complex_rolling_agent_v0.3` 使用同一 XA 规则、同一订单种子、12 家企业和保守/混合/激进三类对手分别运行一场配对实验。结果保存在 `data/experiments/owned_agent_complex_v1/results.json`。

| 指标 | 固定基线 | 复杂滚动 Agent |
| --- | ---: | ---: |
| 场次 | 3 | 3 |
| 平均得分 | 288.31 | 70.01 |
| 平均排名 | 1.33 | 4.33 |
| 破产率 | 0% | 0% |
| 出现违约的场次比例 | 100% | 0% |
| 平均获单 / 交付 | 2.33 / 1.00 | 3.67 / 3.67 |
| 平均最低现金 | 51.00 | 53.67 |
| 平均产品 / 市场 / ISO 资格 | 1 / 1 / 0 | 4 / 4 / 1 |

复杂 Agent 已覆盖产能、融资、履约、市场、生产、资格和供应七个动作域，三场均无破产、无违约、无非法动作，并把所有获得的订单全部交付。这证明复杂动作生成、联合排程、状态机校验和反馈闭环已经可以连续运行 20 个季度。

但它的平均权益和正式得分显著低于固定基线，主要因为资格开发范围过大、权益保留不足、产能仍集中在一条基础线，尚未把高发展潜力有效转成订单利润。因此当前结论是“复杂决策基础能力完成，收益优化未完成”，不能把该版本称为已优于人工或已达到验收标准。

## 历史鲁棒性实验

实验使用固定 XA 参数、27 家企业、796 个随机内容但保持 XA 年度数量形状的订单，以及 3 个订单种子 × 3 类对手组合。每组分别运行原固定基线和单企业鲁棒 Agent，共 18 场完整比赛。只替换我方企业策略，其他条件在配对内保持一致。

| 指标 | 固定基线 | 单企业鲁棒 Agent |
| --- | ---: | ---: |
| 场次 | 9 | 9 |
| 平均得分 | 345.39 | 405.25 |
| 平均排名 | 6.78 | 3.89 |
| 破产率 | 0% | 0% |
| 出现违约的场次比例 | 0% | 0% |
| 平均所有者权益 | 292.70 | 292.18 |
| 平均发展潜力 | 18.00 | 38.67 |
| 平均获单 / 交付 | 2.22 / 2.22 | 4.11 / 4.11 |
| 平均最低现金 | 170.67 | 80.32 |

鲁棒 Agent 平均得分提高 59.86，平均排名改善 2.89 位，9 场中 6 场得分高于基线。提升主要来自在权益基本持平的情况下把发展潜力提高约 20.67，并把交付订单数提高约 85%。但最低现金明显下降，且在订单种子 `20260830` 的保守和混合对手场景中仍低于基线，说明当前版本尚未达到策略最优或可直接无人值守部署的程度。

首轮失败实验被保留为 `results_v0_1_failed.json`。当时规划器错误地把“订单分配后的季度推进”少计算了一个动作窗口，导致 22.2% 破产、88.9% 场次出现违约。修正后的交期过滤要求：有现货也必须留出下一次交付动作窗口；需要生产时还必须额外覆盖安装/生产周期和交付动作窗口。失败记录用于回归验证，不能作为当前策略性能。

## 当前实现与继续完善

当前版本已经是可执行的复杂单企业 Agent 基础系统，具备私有观测隔离、七域经营候选、多订单组合、共享产线排程、滚动现金情景、对手不确定性、可选付费信息、环境裁决和反馈更新。它还不是“已证明优于人工”的生产系统，后续最高优先级是减少无效资格投入、增加按订单组合决定的多产线扩张、提高权益与正式得分，并扩大订单种子、企业数量、对手组合和规则扰动留出测试。

VPD 已被定义为最终 Agent—人工配对验收的主指标，与 VPD/OE、正式得分、破产率、违约率和最低现金一起使用。`decision_acceptance.py` 要求两条轨迹具有相同规则、订单种子、对手组合、接入时点和初始状态；硬约束失败时，即使 VPD 更高也不能通过。VPD 不参与在线单步动作选择。旧 VPD/OE 计算口径尚需与 XA 的统一会计分配逐项校准，因此当前绑定状态仍是候选验收口径。

核心代码位于 `src/goai_data/owned_agent.py` 和 `src/goai_data/decision_acceptance.py`，实验入口为 `scripts/run_owned_agent_robustness.py`，当前结果保存在 `data/experiments/owned_agent_complex_v1/`。
