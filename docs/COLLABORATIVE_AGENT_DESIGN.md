# 单企业多模块 Agent 协同决策设计

## 目标与边界

本系统中的“多 Agent”不是让多个 Agent 分别控制不同参赛企业，而是让六个专业 Agent 共同服务于我方同一家企业。其他企业仍由环境中的对手模型控制，我方系统只能读取本企业私有状态、当前已发布的公共订单和规则允许公开或购买的信息，不能读取对手私有操作、未来订单、真实终局归属或裁判内部轨迹。

六个专业 Agent 不分别提交动作。它们先在同一个 `SharedDecisionBlackboard` 上提出相互依赖的方案，再由协调器形成一份季度联合动作包，最后由确定性财务状态机重放并由风险 Agent 删除不可承受的动作。这样可以避免“订单 Agent 认为订单有利润、产能 Agent 却没有对应产线、财务 Agent 又无法支付当季原料和贷款”的局部最优。

| 专业 Agent | 负责内容 | 必须读取的跨模块约束 |
| --- | --- | --- |
| 资金 Agent | 现金准备、应收贴现、受订单支持的短期桥接融资 | 期初结算、未来材料付款、维护、租金、研发、贷款到期和订单回款 |
| 资格 Agent | 产品、市场和 ISO 开发 | 可见订单需求、研发完成时点、剩余季度、现金和权益 |
| 产能 Agent | 厂房、产线和扩产节奏 | 全部在手订单、产品结构、投产时点、固定费用和已实现交付 |
| 供应与履约 Agent | 普通采购、紧急采购、生产、库存和整单交付 | BOM、共享产线、订单数量、交期、库存和现金 |
| 订单组合 Agent | 选单、竞单、广告和组合容量占用 | 资格、整批生产能力、已有承诺、利润、对手不确定性和广告优先规则 |
| 风险批评 Agent | 对完整动作包做确定性重放和预算裁剪 | 现金、权益、期初结算、年度固定成本、未来材料付款及保守订单利润 |

当前实现位于 `src/goai_data/collaborative_agent.py`，版本为 `owned_enterprise_specialist_committee_v0.9_executable_capacity`。第一阶段读取观测并建立共享黑板，资金、资格、产能、供应履约和订单组合模块提出相互依赖的方案，风险模块重放完整动作包；环境随后统一解决订单冲突。启用 `post_allocation_phase` 时，同一季度不会立即结算，而是返回实际获单结果；资金、产能、供应履约和风险模块针对全部实际在手订单再次联合规划融资、扩厂、建线、采购、生产和交付，第二次提交后环境才执行违约、财务结算和季度推进。`allow_prospective_new_cell` 仍为默认关闭的消融接口，网页推荐和协同对手会显式开启该能力。

双阶段不是让 Agent 获得裁判私有信息。第二阶段只能看到本企业新增在手订单和公开分配结果，其他企业的库存、现金、产能和未公开操作仍不可见。环境继续独立判定动作合法性、冲突赢家、库存变化、违约和破产；Agent 的“预计不破产”不改变裁判结果。

VPD 不用于替代上述联合规划，也不负责决定某一个孤立动作。它作为离线验收指标，在相同规则、初始状态、订单种子、对手组合和接入时点下比较 Agent 与人工完整轨迹。

供应履约 Agent 对到期订单的紧急成品补货使用完整增量权益判断：订单收入与避免的违约罚款必须能够覆盖已有库存账面成本和新增紧急采购成本。这样不会为了保持表面交付率而执行降低终局权益的订单补救。订单组合 Agent 同时记录资格、已有承诺容量、联合组合容量、毛利和生命周期目标等淘汰原因，便于把“获单少”定位到具体约束，而不是无依据放宽接单。

## 指标计算口径

报告必须同时区分“存续企业口径”“全体企业口径”和“订单口径”。当前实验脚本已把定义写入每个 `calibration_report.json` 和汇总 `summary.json`。

- 存续企业平均权益：所有未破产企业的终局所有者权益之和除以未破产企业数。真实 XA 为 18 家存续企业的权益均值 584.22 万元；破产企业不进入这个均值。
- 全体企业平均得分：所有存续企业终局得分之和除以全部 27 家企业数，破产企业按 0 分处理。真实 XA 为 1046.26。
- 存续企业平均得分：存续企业终局得分之和除以存续企业数。真实 XA 为 1569.39。
- 平均获单：有终局赢家的订单数除以全部参赛企业数。真实 XA 为 561 / 27 = 20.78 单/企业。
- 平均交付：`order_delivered` 事件数除以全部参赛企业数。真实 XA 为 544 / 27 = 20.15 单/企业。
- 获单后交付率：已交付订单数除以已分配订单数。真实 XA 为 544 / 561 = 96.97%。它与“平均交付”不是同一个指标；前者测履约质量，后者同时受获单规模影响。
- 发展潜力：按产品、市场、ISO、自有厂房和已完成产线的正式分值求和；终局得分再由所有者权益与发展潜力乘数共同决定。

## 2026-08-11 三种子结果

实验固定使用 XA 参数、27 家企业、20 个季度和 796 条经验形状订单，不读取终局订单归属或企业未来路径。种子为 `20260811`、`20260812`、`20260813`，正式机器结果位于 `data/experiments/xa_collaborative_calibration_v8/summary.json`。

| 存续企业平均得分 | 490.88 | 811.28 | 1569.39 | 51.69% |

| 存续企业平均权益 | 212.83 | 337.58 | 584.22 | 57.78% |
| 存续企业平均发展潜力 | 129.41 | 136.71 | 149.67 | 91.34% |
| 每场获单 | 302.67 | 354.00 | 561 | 63.10% |
| 平均获单 | 11.21 | 13.11 | 20.78 | 63.10% |
| 每场交付 | 235.00 | 273.33 | 544 | 50.25% |
| 平均交付 | 8.70 | 10.12 | 20.15 | 50.25% |

v0.6 在 v0.3 的冲突回退、原料滚动和订单驱动扩产基础上，进一步完成六项修正：稳定基础产能采用购买厂房、突发容量才租赁；成品库存进入订单组合容量；回退订单只能复用同产品且不早于主订单的容量；成长型企业在无订单的第一年建立两条自动线，平衡型和保守型仍一线起步；P2→P4、P3→P5 的半成品 BOM 进入供应计划；到期短贷可按当前规则足额滚动，风险预演同时计入年末折旧。相对 v0.3，存续数增加 3 家，平均得分提高 320.40，权益提高 124.75，每场获单增加 51.33、交付增加 38.33。全部运行仍保持会计平衡且动作拒绝为 0。

交付率没有随着获单同步提高：v0.6 比 v0.3 低约 0.42 个百分点，但绝对交付增加 16.31%。主要原因是聚合校准中的 9 家旧激进对手仍在 Y2Q4–Y3Q1 过早破产并留下悬空订单。独立压力场 `data/experiments/xa_late_failure_stress_v2/summary.json` 把这些对手改为先正常经营、再于中后期过度扩张，三种子平均获单 349.33、交付 299.33、交付率 85.68%，同时平均存续 17.33 家；这说明订单生命周期而非评分公式是交付率差距的重要部分。

v0.6 仍未达到“与真实比赛相差不大”：平均交付只有真实的 50.25%，权益和得分分别为真实的 57.78% 和 51.69%。不过发展潜力、自有厂房和存续分布已经接近，剩余瓶颈已收敛到平均 6.43 对 8.83 的产线规模、P4/P5 供应链吞吐、订单分配阶段以及获单后的跨季度完整交付。不能通过放大初始现金、降低正式成本或改写评分公式补分。

## 下一版实施顺序

1. 把当前启发式滚动组合升级为跨 4–8 季度的订单—产能—物料—现金联合搜索，显式表示不同产线的安装期、生产周期、同产品批次、订单完整交付、回款和贷款到期。
2. 为模拟对手建立冠军扩张型、均衡型、细分市场型、保守型和破产型的异质策略，不再让大量企业同时争夺相同的小额订单；用真实公开行为校准广告、市场、产品和 ISO 分布，但不把真实未来路径暴露给在线 Agent。
3. 将扩产条件改成“已实现利润 + 高置信在手订单利润能够覆盖投资、维护、折旧、利息和到期偿债”，并允许手工线、自动线、柔性线之间做完整生命周期比较。
4. 增加年度订单需求预测和正常原料采购，在订单释放前准备适量原料；继续保留紧急采购作为交付兜底，并把其额外成本计入订单边际利润。
5. 先把基准获单后交付率从 77.23% 提高到至少 90%，再把平均获单从 13.11 提高到 18 以上、平均交付从 10.12 提高到 17 以上；只有吞吐和利润上升后，才继续增加产线和高阶产品，避免用无收入支撑的发展投入制造破产。
6. 每次改动都在至少三个订单种子和多个对手组合下比较存续、最低现金、权益、获单、交付、交付率、发展潜力、正式得分和 VPD；不得通过放大初始现金或修改正式 XA 计分参数来伪造接近结果。

## 2026-08-12 协同 Agent v0.7 校准与消融

正式基准使用 `scripts/run_xa_population_calibration.py --survivor-policy collaborative --output-root data/experiments/xa_collaborative_calibration_v12 --seeds 20260811 20260812 20260813`，机器结果位于 `data/experiments/xa_collaborative_calibration_v12/summary.json`。v0.7 默认保持 v0.6 的稳健经营策略，三种子均值为 17.33 家存续、9.67 家破产，存续平均得分 811.28、权益 337.58、发展潜力 136.71；每场获单 354、交付 273.33、获单后交付率 77.23%，全部会计平衡且动作拒绝为 0。指标分别达到真实 XA 的 51.69%、57.78%、91.34%、63.10%、50.25% 和 79.64%。

本轮对照实验拒绝了三类默认修改：统一手工线使交期和存续恶化；一次性为订单缺口融资使负债和破产上升；无条件预生产和新产品单元使订单收入不足以覆盖新增库存、组件链和固定费用。v0.7 将新产品单元保留为可消融开关，只有显式构造 `CollaborativeEnterprisePolicy(..., allow_prospective_new_cell=True)` 才启用，默认在线 Agent 不使用。结论是当前差距主要仍来自产线吞吐、订单分配后的同季度经营阶段和 4–8 季度现金—BOM—产能联合搜索，不能用评分公式或初始现金修补。

## 2026-08-13 v0.9 可执行产能协同

`owned_enterprise_specialist_committee_v0.9_executable_capacity` 保持六专业 Agent 控制同一家企业的结构，但修正了订单与履约模块之间的状态语义。订单模块现在按状态机真实的产线安装、忙碌任务、生产周期、现有库存和终局季度计算订单可执行容量；履约模块不再把自动线已即时入库的产品同时算作在制品，并按产品 BOM 拓扑先安排 P2/P3，再安排 P4/P5。动作包仍需完整通过风险 Agent 的确定性重放，提交后还必须由比赛环境再次执行和判定，因此 Agent 的预测不会替代环境的违约或破产结果。

网页中的协同对手与“获取 Agent 建议”默认开启有界 P1–P3 新产品单元。该能力只允许订单组合为一个尚无产线、但已具备产品资格的基础产品预留有限未来容量，并要求现金和权益达到门槛；分配后阶段必须真实完成厂房、产线、物料和生产动作。实验脚本继续用 `--allow-prospective-new-cell` 显式控制该策略，以保持开/关消融能力。

三种子 v17 均值为：存续平均得分 1536.90、权益 619.36、发展潜力 142.66；每场获单 497.67、交付 464.33、获单后交付率 93.26%，存续企业平均完成产线 7.97。相对真实 XA 分别达到 97.93%、106.01%、95.32%、88.71%、85.36% 和 96.18%。当前评分与权益已经接近真实数量级，剩余主要差距是绝对订单吞吐、种子间交付波动以及模拟破产数偏少，而不是交付动作缺失或评分公式偏低。
