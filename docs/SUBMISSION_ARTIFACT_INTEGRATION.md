## 三个新增文件的作用

`artifact/企业经营决策Agent_作品简介.docx` 是 469 字的作品简介，适合直接作为初赛简介的内容底稿；`artifact/企业经营决策Agent_项目书.pptx` 与 `artifact/企业经营决策Agent_项目书.pdf` 是同一套 15 页项目书及其导出版本，适合作为 PPT/PDF 的视觉主稿。三份文件均位于本地 `artifact/`，已被 `.gitignore` 排除，不会随开发仓库提交。

新项目书的优点是企业叙事、跨部门痛点、六步经营闭环、技术架构、企业价值、团队分工和开源路线完整，视觉上已经具备正式提交的基础。它的叙述对象偏向“订单驱动制造企业经营计划”，而当前已完成并有浏览器验收证据的对象是“XA 企业经营沙盘中的单个参赛企业辅助决策”。两者可以统一，但不能让评委误解为已经接入真实 ERP、CRM、MES 或 WMS 生产系统。

## Demo 应该使用什么页面

应使用当前 GoAI Web 页面 `http://127.0.0.1:8765`，因为它能直接证明“可点击、可提交、可反馈”，比只录 PPT 动画更有说服力。录屏主体建议占 70%–80%，PPT 只承担开场定位和结尾指标。

推荐录制顺序如下：

1. 在大厅创建 6 家企业、1 名人类席位的 `人类 + Agent` 赛局，选择异质经营对手；页面显示创建码、席位和 XA 规则。
2. 进入比赛后展示我方现金、权益、资格、产线、库存和当前阶段；强调这里只显示我方私有状态及允许的公开订单，不显示对手私有状态。
3. 点击“让协同 Agent 生成方案”，展示待提交动作包；删除一个非必要扩产动作或调整贷款期限，再点击提交，证明人工拥有最终确认权。若在订单页勾选多个同产品订单，也可以点击“组合申领（含回退）”，展示系统生成有序回退候选。
4. 第一阶段结束后展示“获单后履约”阶段。此时广告、资格和订单申领控件会被禁用；展示实际获单并再次获取采购、生产和交付建议。
5. 提交履约方案，进入下一季度；在“报表与反馈”页展示裁判反馈、现金变化、交付/违约状态和会计平衡结果。
6. 返回大厅创建 0 人类席位的纯 Agent 赛局，点击“推进一个阶段”展示双阶段切换，再点击“运行至终局”，展示 20/20、排名和导出按钮。
7. 最后切回 PPT 第 10 页或单独结果页，展示 v17 的聚合指标，不打开完整 JSON、代码、原始 XLS/XLSX 或开发者工具。

排练时可以预先推进到 Y2Q1，因为 Y1Q1 的公开订单可能为空，Y2Q1 才能稳定展示订单池和申领表格。若希望完整展示从零开始的因果流程，则录制 Y1Q1 的资格/产能建设，再录到 Y2Q1 的订单申领；不要为了让画面一开始有订单而修改规则时序。

## 录制前检查

- 使用新生成的模拟种子和 `TEAM_01` 等占位企业名，不使用真实队伍映射。
- 启动 v0.4 服务并确认 `/api/health` 返回 `goai_clickable_competition_v0.4_complete_controls`。
- 浏览器窗口至少 1440×900；字体缩放 100%；录制前关闭开发者工具、终端、文件管理器和通知。
- 先排练一轮人机赛，再排练纯 Agent 终局；不要把排练加入码、令牌或完整导出文件放进画面。
- 录制时只展示聚合结果和我方观察；如果打开“全局订单”，确认订单归属尚未泄露。
- 视频结束前显示一次人工修改动作和一次环境反馈，这是最能证明系统不是静态 PPT 的两个证据。

## 新材料需要避免的表述

- “已接入 ERP/CRM/MES/WMS 生产系统”：当前应改为“已设计标准接入层，当前以 XA 沙盘和模拟数据验证”。
- “完全还原真实 XA 裁判”：当前只能说“按观察规则和传统沙盘补全，并经过数量级校准”。
- “Agent 保证不破产/一定交付”：最终结果由环境依据提交后的状态判定。
- “准确率、模型数量或早期 VPD 数字”：除非能在当前实验产物中逐项核验，否则删除；结果以 v17 `summary.json` 为准。
- “公开仓库即可复现”：公开仓库和完整参数会增加竞赛策略泄露风险；初赛材料使用脱敏展示分支。

## 结论

新三份文件可以与当前系统合并使用：保留 15 页项目书的视觉和企业价值主线，用当前 `SUBMISSION_DRAFT.md` 的 v0.4、v0.9、v17 内容校准技术页、验证页和 Demo 讲解；实际录屏使用 GoAI 操作页面，不需要另做静态原型。这样评委既能看到完整的产品叙事和工作量，也能看到真实可点击的比赛闭环，同时不会把当前原型误认为已经完成企业生产接入或泄露完整复现条件。
