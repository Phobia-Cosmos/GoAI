# GoAI 当前版本总结

更新日期：2026-08-13

## 当前结论

GoAI 已形成一套可运行的 XA 企业经营比赛基础系统：它可以生成 27 家企业、5 年 20 季度和 796 条经验形状订单的完整比赛，由确定性环境统一处理资格、订单竞争、融资、厂房、产线、BOM、采购、生产、交付、违约、税费、折旧、报表、破产和排名；我方一家企业可由人工操作，也可由六个专业 Agent 协同提供建议。当前版本已达到“主要经营指标接近真实 XA 数量级”的阶段目标，但不是对真实 XA 每一条历史轨迹和终局数字的精确复刻。

当前正式基线为：

- 协同 Agent：`owned_enterprise_specialist_committee_v0.9_executable_capacity`。
- 点击比赛平台：`goai_clickable_competition_v0.4_complete_controls`。
- 正式校准实验：`data/experiments/xa_collaborative_calibration_v17/summary.json`。
- 测试状态：106 项自动测试全部通过，Python 编译、JavaScript 语法和 Git 差异格式检查通过。
- 运行入口：`http://127.0.0.1:8765`。

## 系统已经具备的能力

1. **统一规则与数据。** XA 规则包、初始状态、企业列表、全局订单、动作、事件、季度状态、报表和终局结果均有结构化契约；真实、推断和模拟字段保留来源标记，终局订单归属不会泄露给在线 Agent。
2. **完整比赛环境。** `FullCompetitionArena` 与 `FullFinancialDynamics` 能从 Y1Q1 运行到 Y5Q4，由环境而不是 Agent 独立判定动作是否合法、谁获得订单、是否交付、是否违约和破产，并生成可审计轨迹与三张年度报表。
3. **双阶段季度流程。** 每季度先提交经营、广告和订单申领，所有企业同步完成订单分配；我方随后只看到本企业实际获单和规则允许的公开信息，再提交融资、扩产、采购、生产与交付方案，最终统一结算。
4. **单企业内部多 Agent 协同。** 资金、资格、产能、供应履约、订单组合和风险六个专业模块共享同一决策黑板，形成一份联合动作包。多个模块服务的是我方同一家企业，不是让系统控制所有参赛企业。
5. **可执行产能与复杂产品链。** Agent 已考虑产线安装完成时间、忙碌任务释放时间、生产周期、库存、在制品、比赛终局边界以及 P2→P4、P3→P5 的 BOM 依赖；风险模块会在提交前用状态机重放完整动作包。
6. **部分可观测与对手模拟。** 在线决策只读取我方私有状态、公开订单和允许购买的信息；本地训练可组合异质经营、晚期扩张压力、协同、保守和启发式对手，并更换订单种子。
7. **可点击比赛平台。** 支持单人对 Agent、多人对 Agent、纯用户和纯 Agent；人工可以逐项构造动作，也可以获取 Agent 联合建议后修改再提交。纯 Agent 赛局可以逐阶段推进或运行至终局；生产支持指定产线，柔性线、竞单报价和贷款期限均有显式控件。真实浏览器验收已跑通创建、启动、两个阶段推荐和提交、进入下一季度、纯 Agent 终局以及移动端布局。

## 与真实 XA 的对照

以下模拟值是种子 `20260811`、`20260812`、`20260813` 的均值，规则参数、27 家企业、20 个季度和 796 条订单规模保持一致。破产企业的正式得分按 0 计入全体平均分；权益、发展潜力和存续平均分只统计未破产企业。

| 指标 | 当前 v17 | 真实 XA | 当前水平 |
| --- | ---: | ---: | ---: |
| 存续 / 破产企业 | 20.33 / 6.67 | 18 / 9 | 模拟少破产 2.33 家 |
| 存续企业平均得分 | 1536.90 | 1569.39 | 97.93% |
| 全体企业平均得分 | 1156.08 | 1046.26 | 110.50% |
| 存续企业平均权益 | 619.36 万元 | 584.22 万元 | 106.01% |
| 存续企业平均发展潜力 | 142.66 | 149.67 | 95.32% |
| 每场获单 | 497.67 | 561 | 88.71% |
| 每企业平均获单 | 18.43 | 20.78 | 88.71% |
| 每场交付 | 464.33 | 544 | 85.36% |
| 每企业平均交付 | 17.20 | 20.15 | 85.36% |
| 获单后交付率 | 93.26% | 96.97% | 相差 3.70 个百分点 |

因此，“接近真实比赛”的依据是存续得分、权益、发展潜力、交付率、产线和厂房均已进入真实 XA 的相近区间；不足之处是每场平均仍少获得约 63 单、少交付约 80 单，且模拟环境的破产数偏少。全体平均分高于真实 XA，主要受模拟存续企业更多和存续权益略高影响，不能解释成 Agent 已经全面超过真实选手。

## Agent 如何工作

每个季度的决策闭环是：观察我方状态和公开盘面 → 六专业模块提出相互依赖的动作 → 风险模块用确定性状态机预演并裁剪 → 人工确认或自动提交 → 环境处理所有企业的订单冲突与状态转移 → 将本企业实际反馈写回 → 下一阶段或下一季度重新规划。反事实动作不是修改历史结果，而是从动作发生的那个状态复制一条模拟分支，重新执行此后的全局环境。

当前系统不需要 LLM 才能运行。规则执行、财务计算、合法性验证、订单分配、搜索基线和专业 Agent 都是确定性代码或启发式策略。后续可以接入开源或商业 LLM，用于理解非结构化题面、生成候选方案、调用工具和解释方案；但 LLM 不能替代规则引擎，也不应直接修改财务状态。现阶段没有必要先用私有数据微调大模型，优先级更高的是积累结构化的“观察—候选—动作—反馈—结果”轨迹，并建立严格离线评测。

## 当前可信边界

- XA 原始资料没有完整暴露正式裁判的全部内部结算顺序，缺失部分采用传统沙盘规则、历史终局约束和显式推断实现，因此当前环境是经过 XA 校准的因果模拟器，不是原比赛服务端源码。
- 真实 XA 历史终局可以做结果回放；只靠现有历史动作表不能无损重算全部季度，因为逐笔生产、库存、应收、失败竞单和部分动作参数并不完整。
- v17 使用三个固定订单种子和一种校准对手总体结构，已经能证明基础效果，但不足以证明对任意规则、任意对手和真实线上异常都鲁棒。
- Web 平台当前适合本机和局域网实验，会话仍在内存中；公网使用前还需要身份认证、持久化、恢复、权限和日志签名。

## 后续建议

当前版本可以冻结为“接近真实 XA 的基础版”，后续不再通过修改正式规则、初始现金或计分公式追平数字。下一阶段应按以下顺序推进：

1. 把 4–8 季度订单、专线、BOM、普通采购、贷款、回款和终局价值做成联合滚动搜索，优先补足获单与绝对交付规模。
2. 扩大订单种子和对手组合评测，加入最差场景、方差、破产概率和策略消融，而不仅比较三种子均值。
3. 完成真实比赛接入适配器，把赛场当前时点之前的本企业动作、当前私有状态、公共订单和允许购买的信息转换成统一观察；保留人工最终确认。
4. 将 VPD 与正式得分、权益、交付、破产率一起作为 Agent 与人工完整轨迹的离线验收体系，避免单一指标驱动策略偏移。
5. 在积累足够真实决策轨迹后，再评估行为克隆、强化学习或 LLM 工具规划；训练目标应是可执行动作和长期结果，而不是让模型记住某一场比赛的终局答案。
