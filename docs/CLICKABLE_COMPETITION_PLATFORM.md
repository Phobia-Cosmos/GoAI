# StratPilot可点击比赛平台

StratPilot现已提供一个不依赖前端框架的本地 Web 赛场，当前平台版本为 `enterprise_decision_arena_v0.8_annual_quarterly_single_submit`。浏览器只负责收集点击操作和展示我方可见信息；所有现金、贷款、资格、采购、生产、订单、报表、违约与破产仍由独立模拟器统一结算，前端和决策智能体都不能直接修改状态。

每次创建比赛都会依据规则种子生成本场独立规则包和比赛规则通知。规则参数来自多场企业经营沙盘归纳出的合理范围，通知明确标记为模拟生成，不显示为某一场历史比赛的固定规则。规则在比赛开始前即可查看，包含产品、市场、认证、厂房、生产线、原料、融资、应急采购、订单冲突、违约、评分参数和各类动作提前期。全赛程订单目录从开局即可查看，但第一年度没有订单，只有进入申领窗口的订单可操作；对手私有动作和最终订单归属不会提前展示。

页面同时提供操作说明、四阶段流程、人类/Agent 席位标识、对手策略解释、自然语言状态问答、Agent 联合决策理由、人机动作一致度和季度/终局复盘。当前状态问答由可审计的确定性工具生成，能够回答我方现金、权益、负债、订单、产能和风险档位等问题，并把用户要求反馈到决策方案；它还不是接入通用 LLM 后的任意开放域问答。未来接入 LLM 时，LLM 只负责问题理解和解释组织，数值、可行动作和风险预演仍必须调用状态机工具。

## 已实现的比赛方式

- 单人对 Agent：创建比赛时设置一个人类席位，其余企业由所选 Bot 策略控制。
- 多人对 Agent：设置多个但少于企业总数的人类席位，玩家凭加入码进入，其余席位由 Bot 补齐。比赛必须等待所有人类席位到齐才能开始；例如设置 6 个人类席位，就必须等待 6 位真实玩家全部加入。
- 纯用户比赛：人类席位等于企业数量。
- 纯 Agent 训练场：页面允许人类席位为 0，可逐阶段推进，也可直接运行至终局。
- 对手强度：可选择异质经营、晚期扩张压力、协同决策、保守基线或随机启发式对手；创建页显著解释每类模拟对手的行为和用途，排名页进一步显示每家模拟企业实际采用的增长领先、平衡扩张、稳健存续、高风险扩张或协同子策略。模拟对手只用于本地形成竞争环境，不代表决策智能体在真实比赛中控制其他企业。
- 年度规划与季度提交：每年第一季度形成年度大规划，后续季度根据实际获单和结算反馈滚动修订。每季度只提交一次完整动作包，环境同步处理所有企业的经营动作、订单冲突、财务结算、违约、报表和破产判定，再进入下一季度。全局订单与本企业已获订单分别展示，其他玩家的私有现金、库存、贷款和动作不会进入我方观察。

经营主界面只显示比赛中可直接使用的本企业现金、负债、产线容量和待履约订单，不显示官方盘面通常不会提供的评分代理。权益变化、过程评分、现金安全线、人机一致度和每次决策依据集中在独立的“Agent 可靠性”页面，并明确标注为系统评估而非比赛官方信息。预演只使用我方私有状态、公开订单和规则允许的信息，不依赖对手私有状态。

应急采购、资产调整和商业情报是常见但可选的沙盘动作。紧急采购用更高价格即时补足原料或成品；转产只对我方已建成产线开放；出售产线或自有厂房按规则回收残值；商业情报只在本场启用时提供有限字段。没有符合条件的产线或厂房时，页面显示明确占位并禁用按钮，不再出现空下拉框。

我方一旦破产，页面会直接提示本场已输并停止继续提交。单人对抗可让模拟对手完成剩余赛程后进入终局复盘；多人真人比赛不能由系统代替其他玩家。正常完成、获胜或失败都会生成终局复盘。

## 可点击动作

界面覆盖短贷、长贷、应收贴现、产品/市场/ISO 开发、厂房购买/租赁/出售、产线建设/转产/出售、普通原料采购、紧急原料与成品采购、生产、订单交付、广告、选单、竞单、组合申领（含同产品且交期不早于主订单的回退候选）和规则允许的信息购买。生产动作可明确选择产线，柔性线会按当前资格显示可生产产品；竞单可编辑报价，短贷期限按季度、长贷期限按年填写。空动作包等价于保持。用户也可以让六专业 Agent v0.9 生成稳健、平衡、增长三套联合方案，再人工删除、增加或修改后提交。当前单阶段赛场只允许已存在或已在本动作包中通过风险审查的产线支撑订单承诺，不把未来可能扩建的产线当作现有容量。

每季度提交后，环境直接完成订单竞争和结算；新获订单写入“本企业订单”，并在下一季度进入履约滚动规划。用户可以返回大厅并清除本地比赛令牌；信息购买遵循本场规则，购买结果只对购买企业可见。

v0.9 在三个 XA 经验订单种子上的均值为 497.67 单获单、464.33 单交付、93.26% 获单后交付率、1536.90 存续平均得分和 619.36 万元存续平均权益。真实 XA 对应为 561、544、96.97%、1569.39 和 584.22。评分和权益已进入真实数量级，但获单和交付绝对规模仍偏低；网页平台应被理解为可运行的训练赛与 Agent 评测环境，而不是声称精确复刻真实比赛的每个终局统计。

比赛结束后页面提供两类下载。“导出比赛 XLSX 资料包”生成与省赛资料同族的 ZIP：赛场子目录内包含第 1 年至第 6 年公共工作簿和每家企业的九 Sheet 工作簿，外层包含本场规则、800 条全局订单及终局归属、最终排名、破产信息、全部企业终局和导出说明；“导出审计 JSON”保存 20 季动作、反馈、订单分配日志和完整状态。两类导出仅在终局开放，不会在比赛进行中泄露其他企业私有状态；初赛公开版应关闭或聚合化导出。

## 接口

- `GET /api/health`：服务健康状态。
- `GET /api/catalog`：企业数、人类席位、Bot 类型和规则包目录。
- `POST /api/matches`：创建比赛。
- `POST /api/matches/{id}/join`：加入人类席位。
- `POST /api/matches/{id}/start`：开始比赛。
- `GET /api/matches/{id}`：取得公开状态；携带玩家令牌时同时返回该玩家的私有观察。
- `POST /api/matches/{id}/recommend`：为我方企业生成六专业 Agent 联合建议；可提交风险风格和用户自然语言反馈，返回动作、决策理由和反馈审查结果。
- `POST /api/matches/{id}/submit`：提交我方本季度动作包。
- `POST /api/matches/{id}/advance`：推进无人类玩家的 Agent 比赛。
- `POST /api/matches/{id}/run`：将无人类玩家的 Agent 比赛运行至终局。
- `POST /api/matches/{id}/autopilot`：在单个人类席位比赛中，让我方 Agent 按当前风险风格逐季度托管至终局。
- `GET /api/matches/{id}/export`：终局后导出完整记录。
- `GET /api/matches/{id}/export-xlsx`：终局后下载比赛式 XLSX 完整资料 ZIP。

## 当前部署边界

这是可供训练赛和局域网比赛使用的 MVP，不是公网生产服务。比赛会话和令牌当前保存在服务器内存中，进程重启后失效；尚未接入数据库、账户密码、TLS、反向代理、限流和断线恢复。若要公开部署，下一阶段应增加持久化会话、正式身份认证、房主权限、赛程管理、服务端日志签名和容器化部署，不能直接把当前开发服务器暴露到互联网。
