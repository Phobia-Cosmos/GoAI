# XA 回放还原度与前向模拟边界

当前系统把“历史结果回放”和“前向因果模拟”明确拆成两层。前者读取 XA 已观察到的现金事件、终局资产和正式结果，用于建立不可篡改的验收基准；后者只允许读取规则、开局状态、当期动作与当期可见信息，用于 Agent 反事实实验。历史回放可以精确还原结果，但这并不自动证明候选前向状态机已经复刻原比赛平台的全部隐藏裁判逻辑。

## 已修复并通过的历史结果回放

旧的 `traditional_final_results.json` 曾按终局现金排序，这与 XA 的正式计分规则不一致。现在终局裁判统一调用模块化规则服务：从资产重算发展潜力，以所有者权益和发展潜力计算分数，排除破产企业，再按正式分数排序。

截至 2026-08-10，`LX_XA` 的自动验收结果如下：

| 验收对象 | 结果 |
| --- | --- |
| 现金事件连续性 | 3,787 条比赛期事件全部通过 |
| 终局现金 | 27/27 家一致 |
| 资产重算发展潜力 | 27/27 家一致 |
| 正式得分 | 18/18 家一致 |
| 正式排名顺序 | 18/18 家一致 |
| 破产企业和破产季度 | 9/9 家一致 |
| 前三名 | XA07、XA13、XA06 |

机器可读结果位于 `data/processed/v2/matches/LX_XA/traditional_final_results.json` 的 `outcome_replay_verification`，其中 `exact_outcome_match=true`。硬约束报告 `traditional_validation.json` 也增加了排名、破产、发展潜力和终局现金检查。历史多企业接口在到达 Y5Q4 后会返回正式终局结果，并在企业私有历史状态中标记实际破产时期。

可单独重新生成 XA 回放，避免改写其他场次的派生产物：

```bash
PYTHONPATH=src /home/undefined/Disk/python-envs/goai-py312/bin/python scripts/run_all_match_replays.py \
  --dataset data/processed/v2 \
  --match LX_XA \
  --seed 20260805
```

## 为什么还不能宣称前向模拟器完全复刻原裁判

历史结果精确一致使用了历史导出的终局状态作为输入；它没有把终局答案注入反事实模拟器。若要求从 Y1Q1 开局、依次输入所有参赛者原始业务决策，并完全由状态转移重新生成每个季度的三张报表、破产时点和终局比分，当前资料仍有以下不可辨识信息：

- 3,787 条比赛期现金事件中，667 条业务参数只有部分字段，另有 20 条尚未解析。典型缺口包括贷款期限或到期批次、交付对应订单、产线实例及转产目标。
- 796 条全局订单提供最终归属和状态，但不包含完整的每次申领、广告投入、竞价报价、失败请求和冲突裁决序列；现金事件中只有 22 条可见的订单授予记录。
- 现金流可以逐笔完全对账，但非现金状态主要只有年度三张报表和终局资产，没有 27 家企业完整的季度库存、在制品、应收、贷款账龄、折旧累计额和所有者权益快照。
- 9 家破产企业没有导出的终局所有者权益，而且多家企业在破产时仍有正现金。例如 XA04 的历史现金停在 829 万元却于 Y5Q1 被判破产，说明负权益或其他结算结果才是关键；仅从现金流水无法唯一还原该时点。
- 税费、折旧、维护、贷款、应收、订单违约以及资产建成在同一季度内的精确结算顺序并未全部在正式规则表中表达。多套候选顺序可能得到相同终局结果，但在反事实动作下产生不同轨迹。

因此当前能力状态应写成：

- `exact_outcome_match = true`：已观察历史轨迹的终局比分、排名和破产结果可以精确回放和验收。
- `causal_dynamics_replay = false`：尚不能证明仅靠完整状态机从业务动作重新生成了原裁判的每个中间状态。
- `counterfactual_simulation = candidate`：完整财务模拟器可以从头运行 20 季并产生破产、报表和排名，但未确定规则仍属于候选传统沙盘语义。

## 对后续模拟比赛的约束

后续模拟器不应为了匹配 XA 而直接覆盖终局权益、排名或破产名单。正确做法是把历史回放作为校准和回归测试的真值层，再逐项降低前向动力学误差：

1. 优先从原始 XLS 补全 667 条部分事件和 20 条未解析事件的可识别参数，并保留无法识别字段的 `missing` 标记。
2. 从年度报表构造逐年会计检查点，对现金、应收、库存、固定资产、贷款、权益和利润分别计算误差，而不是只对终局得分。
3. 将结算顺序、破产判定、订单冲突和信息可见性做成可替换规则模块，用 XA 的历史检查点筛除不可能的候选组合。
4. 用真实 27 家企业的扩张、融资、订单和破产轨迹校准对手策略分布；随机场景只改变比赛开始时未知的信息，不读取真实终局答案。
5. 当 Agent 改变任一动作时，从改变季度开始重新运行全部受影响企业和全局订单分配，不能继续沿用历史终局状态。

这种分层可以同时保证两个目标：历史 XA 的验收结果准确，随机模拟与反事实环境又不会通过“抄答案”制造虚假的还原度。
